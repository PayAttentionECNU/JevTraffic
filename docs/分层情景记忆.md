# 路口分层情景记忆

在某个相位继续放绿时，排队增加了多少、实际放走了多少车？`CaseMemory` 把已完成模拟日里的观测按动作汇总，下次遇到相似车况时，把这两项结果附在 Jev 本来就要回答的问题上。开关默认是 `off`，与短期触发器的 `--memory`、LoRA 的 `--adapt` 各自独立。

## 一条记录如何形成

每次 SUMO 完成一步后，用动作前的车道排队、放行、绿灯和 V2X 广播构造检索键，读取动作后实际亮起的相位。记录“保持”或“切换到哪个相位”，以及下一间隔全路口排队数的变化和离开进口车道的车辆数。每条进口车道只计一次。切换可能经过黄灯，两项指标按实际经过的秒数折合到每 5 秒。记录覆盖强制动作和预案动作，因此这些均值描述历史相关性。

每天正常结束后，程序将完整轨迹一次性提交到本地 SQLite。相同数据可重复提交，使用同一日号写入不同轨迹会报错。路口、easy/normal 路网、动作空间各用独立档案。模型的判定、事故注入标签和未来交通量均不参与检索。同一模拟日内的相邻帧不会让案例提前达到跨日门槛。

原有 `decisions.jsonl` 继续供 LoRA 使用。旧记录缺少逐车道放行量与动作后的观测，新案例从启用采集的完整仿真开始积累。`read` 要求指定已有档案，`online` 可以从空库启动。

## 从粗到细的四层

1. **可见情景**。分为普通车流、绿灯下有积队且本步零放行、V2X 上报的车型组合。第二类可能由多种原因造成，单步记录保留观测含义。
2. **排队分布**。空路口、积队偏向当前绿灯、偏向其余方向、或较均衡。以当前绿灯服务的车道占全路口积队的 35% 和 65% 为分界。
3. **具体位置**。加入当前相位、压力最大的相位，以及观测到的特种车运动或零放行车道。
4. **时间条件**。加入仿真开始后的 5 分钟窗口和绿灯持续区间。此层可给出最近一次案例的日号、秒数和实际观测结果。

例如，同一路口过去几天的救护车都从西侧左转进入。今天换了进口方向，位置分支没有足够支持时，查询可以回到“救护车、积队偏向红灯方向”这一层。若该车型在可用历史里只出现过一天，模型沿用现场观测和原有 V2X 预案。

每个节点分动作累计证据。从最具体的可匹配节点回退，某个动作至少要有 **3 个决策间隔、2 个不同模拟日**。查询与该节点动作原型的相似度为四个归一化特征的平均绝对距离用 1 相减，特征依次为每车道积队、绿灯积队占比、绿灯持续时间和每车道放行。原型与结果均值采用 7 天半衰期，仅加载过去 28 天，当前日和未来日不可见。

设观察间隔数为 (n)、出现天数为 (d)、距最近出现的天数为 (a)。支持度为 `sqrt(n/(n+3) × d/(d+2))`，近期性为 `2^(-a/7)`，检索分数为 `similarity × sqrt(support × recency)`。相似度至少 0.75、分数至少 0.42 才返回。阈值是工程初值，分数用于证据排序。每次只取一个深度，最多返回两个动作的历史结果，避免父子节点重复计数。参数若需调整，应在独立验证日完成后再测试。

## 使用与对照

- `collect` 只采集，可以用 MP 在无模型权重的环境建立档案。
- `read` 冻结档案，仅检索日号更早的案例。适合配对评测。
- `online` 每日先读历史，运行后再发布当天的观测。适合观察记忆逐日积累。
- `off` 使用原控制流程。无命中时 Jev 收到与该模式相同的状态文本。

在项目的 SUMO 环境中可直接运行。下列 Bash 命令用项目的日需求生成器准备三个不同的模拟日，前两天采集，第三天在相同路线和事件上做对照。

```bash
python -c "from jevtraffic.days import make_day; [make_day('France_Massy', 'normal', d, 'records/case_routes') for d in range(3)]"
for d in 0 1; do
  python run_sumo.py --junction France_Massy --env_name normal_fluctuating_commuter \
    --route_file "records/case_routes/France_Massy_normal_day00${d}.rou.xml" \
    --agent mp --detector rule --events event_1 --case_mode collect --case_day "$d" --case_store records/case_demo
done
for mode in off read; do
  python run_sumo.py --junction France_Massy --env_name normal_high_density \
    --route_file records/case_routes/France_Massy_normal_day002.rou.xml \
    --agent mp --detector rule --events event_1 --case_mode "$mode" --case_day 2 --case_store records/case_demo --save_steps
done
```

MP 的同日对照可检验历史证据能否预测已执行动作的结果。要测 Jev 的控制效果，在测试命令中把 `--agent mp --detector rule` 改为 `--agent jev --detector jev --model <模型路径> --adapters <适配器路径>`，两组使用完全相同的权重、事件、种子和路线。保持／切换模型需要在采集和测试两侧都传 `--action_type next_or_not`。

按天运行原有长期实验时，使用 `python scripts/run_days.py --junction France_Massy --shared ckpt/sumo-distill --adapt off --case_mode online`。可将 `--case_mode` 改为 `off` 比较相同模拟日，或用 `collect` 建库再用 `read` 做固定历史的比较。当同时启用 LoRA 门控时，候选与当前模型在回放中读取相同的历史快照，两个回放都不会写入案例。

## 怎样读指标

`summary.case_memory` 给出查询数、命中数、各可见情景的覆盖率、命中深度和单次内存查询均耗时。开启 `--save_steps` 后可检查每次命中的动作、相似度、支持度、近期性、层级及深层案例。均耗时只覆盖特征构造与内存查询。新增提示的前向开销应看 Jev 模型计时和整局耗时。

`paired_intervals` 只统计有命中且实际执行相位在返回结果中的间隔。`paired_mae` 比较树检索和仅按动作汇总的历史均值，对同一批间隔分别计算排队变化和放行量的平均绝对误差。两侧都只使用过去天数，使用相同的时间衰减。报告 MAE 时应同时给出分母和覆盖率，尤其关注特种车和封道分支冷启动。

控制效果另看 ATT、AWT、特种车 timeLoss、封道误报和额外调用率。比较时冻结历史，使用留出种子，并分别报告无事件、官方事件和随机事件。

## 三个留出路口的实测

在 SUMO 1.28.0 上，Massy、松岛和香港 YMT 各用两个模拟日的官方事件数据建库，后三天分别使用官方事件、随机事件、无事件。控制器为 MP 加规则预案，动作空间为保持／切换。下列命令逐路口生成路由、运行配对实验，结果写入 `records/case_eval/<路口>/next_or_not/paired.json`。

```bash
for j in France_Massy SouthKorea_Songdo Hongkong_YMT; do
  python scripts/eval_case_memory.py --junction "$j"
done
```

9 个测试局共查询 1,444 次，命中 1,406 次。其中最细层命中 1,120 次，另有 286 次退回较粗层。在返回结果包含实际执行动作的 1,370 个间隔中，树检索与只按动作汇总的历史均值相比，排队变化 MAE 从 1.735 降至 1.380，放行量 MAE 从 1.918 降至 1.095，单位为辆／5 秒。两个模式的 MP 动作序列和交通指标逐局相同。

分情景看，普通车况命中 1,402/1,402，绿灯积队且零放行命中 4/4，V2X 车型命中 0/38。因此这组误差改善主要来自普通车流。统计的是查询间隔，同一辆特种车可出现多次。逐局指标、深度与覆盖见[实验数据](../results/sumo/case_memory_benchmark.json)。

针对 V2X 冷启动又做了一次配对检查。固定第 7–9 日的路线、事件、控制器和所有阈值，同一批 22 个 V2X 查询间隔，仅用第 0–1 日建库时命中 2 个，使用第 0–6 日时命中 15 个。七天档案同时包含更多、也更近的观测，这个对照反映两者的共同作用。复现时在上述命令后加 `--first_test_day 7`，分别指定 `--history_days 2` 和 `--history_days 7`。

用项目 0.5B 蒸馏模型验证控制收益时，在同一脚本后加 `--model <Qwen2.5-0.5B-Instruct路径> --adapters ckpt/unitsa-jev-0.5B-full --out records/jev_case_eval`。脚本将采集用的 MP 档案冻结，再在相同模拟日对比两次 Jev。仓库将该适配器列为服务器权重，本次本地实验使用 MP 检验了检索质量。

## 方法来源

XMatch 在时序预测中逐层增加外生匹配条件，用相似度与历史支持控制精细程度。本实现把这一取舍落实为可审计的交通观测前缀和跨日计数，按既有控制器的时延预算检索，无须训练原型编码器。[XMatch，§3.2–3.3](https://arxiv.org/html/2609.34939v1)

REG-TSC 研究了从历史紧急事件检索经验辅助信号控制。本实现保留了 V2X 车型和运动方向，并由现有 Jev 问题与事件预案消费历史信息。[REG-TSC](https://arxiv.org/abs/2510.26242)
